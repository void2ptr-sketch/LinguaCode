# Goal: Keep user-facing strings consistent; document the current localization approach.

## Current state

- The app UI is **hardcoded in Russian** (buttons, labels, hints, empty states, errors). There is **no Angular i18n / `@angular/localize`** setup, no translation files, no `$localize` tags.
- This is the **current project convention** — do not introduce an i18n framework without an explicit task in `TASKS.md`.

## Rules

- New UI strings are written in Russian, matching the tone and style of existing screens (e.g. `Удалить`, `Редактировать`, `Сценариев пока нет.`).
- Domain terms and code identifiers stay in English (see `02.architecture.01.project-architecture.rule.md` §4); technical labels inside UI (e.g. "IPA", "Pinyin") keep their original spelling.
- **Error messages must be user-friendly and localized** — Russian for UI, never raw exception text or internal codes (see `05.business.03.errors-http.rule.md`).
- `aria-label`s and accessibility text are also in Russian where they describe UI (see `04.design.02.a11y.rule.md`).
- If multi-language UI is ever requested, it becomes a dedicated task: add `@angular/localize`, extract strings, update CI/build, and update this rule — do not half-migrate.
