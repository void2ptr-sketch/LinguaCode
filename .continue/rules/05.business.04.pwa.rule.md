# Goal: Keep the PWA/service worker configuration consistent and safe to update.

## Setup (current state)

- Service worker is registered in `src/app/app/app.config.ts`:
  `provideServiceWorker('ngsw-worker.js', { enabled: environment.production })` — enabled only in production.
- Config lives in `ngsw-config.json`; manifest in `public/manifest.webmanifest`.

## Asset groups (`ngsw-config.json`)

| Group | installMode | Resources | Purpose |
| ----- | ----------- | --------- | ------- |
| `app-shell` | prefetch | `/index.html`, `/*.css`, `/*.js`, fonts, manifest | app shell — must be cached at install |
| `content-seed` | prefetch | `/data/**/*.json` | content fixtures — cached at install |
| `hanzi-stroke-data` | lazy | `/assets/hanzi/**/*.json` | large stroke data — cached on demand |

- **Do not move a group from `lazy` to `prefetch` without a reason** — `hanzi-stroke-data` is lazy deliberately (large payload).
- When adding new static resources (fonts, icons, data files), add them to the appropriate asset group; otherwise they will not be cached offline.

## Data groups

- `api` group: `/api/**`, strategy `freshness`, `maxSize: 100`, `maxAge: 6h`, `timeout: 10s`.
- New API endpoints under `/api/**` are covered automatically; do not add separate data groups for them unless caching behavior must differ.

## Rules

- **Never edit `ngsw-worker.js`** — it is generated by the Angular build.
- After changing `ngsw-config.json` or `manifest.webmanifest`, verify with `npm run build:prod` (the service worker is only generated for production builds).
- Keep the manifest in sync with the app: `name`, `short_name`, `start_url`, `theme_color`, icons.
- Do not cache sensitive user data in the service worker; the `api` data group caches only `/api/**` responses with freshness strategy.
- Offline behavior must not break the sync queue (see `05.business.03.errors-http.rule.md`) — mutations are queued and replayed when the network returns.
