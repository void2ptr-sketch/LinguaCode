# Goal: Standardize component/service scaffolding patterns used across the codebase.

## Change detection

- **Every standalone component must use `ChangeDetectionStrategy.OnPush`** — this is the project-wide pattern:

  ```typescript
  @Component({
    changeDetection: ChangeDetectionStrategy.OnPush,
    selector: 'app-user-profile',
    ...
  })
  ```

- Do not use `Default` change detection in new components. Rely on signals/inputs/outputs for reactivity.

## Dependency injection

- Use the **`inject()` function**, not constructor parameter injection, in components, services, guards, and interceptors:

  ```typescript
  private readonly userStore = inject(UserStore);
  private readonly logger = inject(AppLoggerService);
  ```

- Injected dependencies are `private readonly` fields (or `readonly`/`protected` when exposed to the template).
- Constructors stay minimal or empty; do not put logic in the constructor (use `ngOnInit`, `computed`, or `effect`).
- DI and provider scope rules: `02.architecture.03.di-providers.rule.md`.

## Fields & exposure

- Expose store/services to templates as `readonly` public fields; keep implementation details `private`.
- Template method calls that are expensive or observable-producing are forbidden — expose properties instead (see `03.angular.03.reactive.rule.md`).

## Lifecycle

- Avoid `ngOnChanges` for signal inputs (see `03.angular.10.signal-inputs.rule.md`); derive state with `computed()` or react with `effect()`.
- Use `DestroyRef` + `takeUntilDestroyed` for RxJS subscriptions inside services; components with signals/inputs rarely need manual subscriptions.
