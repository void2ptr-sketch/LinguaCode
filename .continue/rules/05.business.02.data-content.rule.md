# Goal: Protect content data integrity when editing fixtures, seed scripts, or migrations.

Full source of truth: `docs/SYSTEM/MOCK-DATA.md` and `docs/ARCHITECTURE.md` (Content Seed & Overlay).

## Data layout

```
public/data/
├── content-manifest.json          ← index of all fixture files (single source of truth)
├── cards/                         ← card fixtures: demo-cards.json, radicals-course-cards.json, …
├── scenarios/                     ← scenario fixtures: demo-scenarios.json, …
├── courses/                       ← course fixtures: demo-courses.json, radicals-214-course.json, …
└── export/                        ← generated PDF files (do not edit by hand)
```

- **`content-manifest.json`** lists every fixture file loaded at startup (`cardFiles`, `scenarioFiles`, `courseFiles`). When adding/removing a fixture file, **update the manifest** — it is the only source of truth for what gets preloaded.
- Fixture files use the shape `{ "cards": [...] }`, `{ "scenarios": [...] }`, `{ "courses": [...], "lessons": [...] }` — keep the wrapper key.
- **Do not edit `public/data/export/`** — it is generated by `scripts/export-course-pdf.mjs`.

## User content overlay (localStorage)

- Key: `lingua-code.user-content.v1` (`USER_CONTENT_OVERLAY_KEY`).
- The overlay stores user edits/creations and is **merged over the seed** at runtime (seed + overlay = catalog).
- Never change the overlay key or its `version` without a migration path; existing user data must survive.

## Critical fields (do not lose during migrations)

- `authoring.status` — `'draft' | 'planned' | 'generating' | 'materialized' | 'failed'`
- `authoring.ideaUpdatedAt` / `materializedAt` / `lastError` — ISO 8601 timestamps
- `id` uniqueness across seed + overlay; `languagePair` (`source`/`target`); `published` flag.

## Seed & content scripts

| Script | Purpose |
| ------ | ------- |
| `npm run export:content-seed` | Export overlay → seed (runs parser + tags tests first) |
| `npm run import:perl-idea` | Import Perl-interview idea from Markdown |
| `npm run import:course-bundle` | Import CourseBundle JSON |
| `npm run generate:radicals-course` | Generate radicals course + export seed |
| `npm run sync:hanzi` | Sync hanzi stroke-data assets |

- Prefer running the existing scripts over hand-editing generated content.
- After any content change, run the relevant script and verify with `npm run verify` (includes `sync:hanzi`).

## Migration rules

- Old format: `{slug}-course.json` with `{courses, lessons}` wrapper; unified format: `all-courses.json` as `[{...}]` array. When migrating, keep both formats' data intact and update `content-manifest.json`.
- Do not drop `authoring.*` fields during migrations (see critical fields above).
- After moving/renaming fixture files, update all references: `content-manifest.json`, seed scripts, and tests (`scripts/import-course-bundle.test.mjs` etc.).
