# Goal: Keep the signal-based store pattern consistent across features and entities.

The project uses **signal-based stores** (`CardSelectStore`, `CardEditorStore`, `CourseBuilderStore`, `ScenarioBuilderStore`, `CourseCatalogStore`, `AuthStore`, `UserStore`, `LearningResultsStore`, `DraftsStore`). A store is a plain `@Injectable()` class — not NgRx, not external state libs.

## Structure

```typescript
@Injectable({ providedIn: 'root' })
export class ExampleStore {
  private readonly userStore = inject(UserStore);
  private readonly logger = inject(AppLoggerService);

  // 1. Private state signals (single source of truth)
  private readonly itemsState = signal<readonly Item[]>([]);
  private readonly loadingState = signal(false);

  // 2. Public readonly derived signals (computed)
  readonly items = this.itemsState.asReadonly();
  readonly loading = this.loadingState.asReadonly();
  readonly hasItems = computed(() => this.itemsState().length > 0);

  // 3. Actions — explicit methods mutating state
  loadItems(): void { ... }
  addItem(item: Item): void { this.itemsState.update((list) => [...list, item]); }
}
```

## Rules

- **State** is `signal<T>()` — private field; expose via `.asReadonly()` (never expose the writable signal).
- **Derived values** via `computed()` (no subscriptions or `BehaviorSubject` in stores).
- **Actions** are explicit methods; mutations use `.set()` / `.update()` — never mutate arrays/objects in place.
- **Async work**: HTTP via injected API/search services; use `switchMap`/`catchError` in RxJS pipelines or `async/await` + try/catch, map results into signals.
- **Error state**: keep `error` signal; surface via `ErrorToastService` and log via `AppLoggerService` (see `20.errors-http.rule.md`). Do not swallow errors.
- **DI scope**: `providedIn: 'root'` for app-wide stores; feature-scoped providers only when isolation is intentional (see `04.angular.DI-PS.rule.md`).
- **Naming**: file `*.store.ts`, class `<Domain>Store`.
- **Tests**: `*.store.spec.ts` with `TestBed.inject(Store)`; mock API/search services (see `07.angular.testing-strategy.rule.md`).
