# Goal: Prevent "зацикливание" — repeating the same command or tool call without progress.

## What counts as a loop

- The same command (or tool call with identical arguments) executed more than **3 times in a row** without a change in approach.
- Re-running a failed command without analyzing the error output first.
- Re-running a command that already succeeded when the expected result is not visible — the state must be verified instead of re-run.

## Rules

1. **Change something between attempts.** Before re-running, ask: "What changed since the last run?" If nothing changed, do not re-run — inspect the error output, read the relevant files, or search the codebase first.
2. **React to the output.** On failure, read the error and fix the root cause. On success with a missing expected result, verify the actual state (files, terminal output, build artifacts) instead of blindly re-running.
3. **Prefer combined commands.** Use `cd dir && command && command` or a single more powerful command instead of several sequential identical tool calls.
4. **Escalate instead of looping.** If stuck, switch strategy: read the docs, search the codebase, or ask the user a clarifying question (see `01.meta.04.tasks-workflow.rule.md`).

## Hard cap

- Never execute the same command more than **5 times** (see `01.meta.01.agent-behavior.rule.md`).
- After **3 identical failed attempts**, stop and re-evaluate the approach — each subsequent attempt must be different (more targeted or diagnostic).

## Escalation

- After the cap is reached, report to the user: what was tried, the observed error/output, and a proposed alternative approach. Do not silently re-run the same command again.
