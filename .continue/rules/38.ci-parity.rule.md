# Goal: Local work must pass the same pipeline as CI before considered done.

## CI pipeline (.github/workflows/ci.yml)

`npm ci` → `sync:hanzi` → `lint` → `format` → `audit:fsd` → `check:imports` → `audit:barrels` → `build:prod` → `test:ci` → conformance tests → `test:coverage` → dependency audit.

## Local parity checklist (before finishing a task)

```bash
npm run verify                                      # lint + audit:fsd + check:imports + audit:barrels + sync:hanzi + build:prod + test:ci
npm run format                                      # Prettier check (CI enforces it)
npx ng test --no-watch --no-progress --include='**/*.conformance.spec.ts'   # conformance suite
npm run test:coverage                               # coverage thresholds (70/65/70/70)
npm run audit                                       # dependency audit (level=high)
```

- Run `npm run verify` at minimum; run the full set when touching tests, data, deps, or configs (see `19.verification-checklist.rule.md`).
- **Do not weaken CI checks** to make a change pass (no removing steps, no threshold lowering, no `continue-on-error` for required steps). If a check is genuinely wrong, fix the root cause or discuss the change explicitly.

## Conventions

- If CI and local environments diverge (versions, platforms), document it in the CI workflow comments — do not hide it.
- New verification scripts added to `package.json` should be added to both `npm run verify` and the CI workflow to keep parity.
