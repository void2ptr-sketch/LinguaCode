# Goal: Use the modern signal-based component API — never `@Input()`/`@Output()` decorators in new code.

The codebase uses `input()`, `input.required()`, `model()`, and `output()` everywhere. Keep that pattern.

## Inputs

- Declare inputs with `input<T>()` (optional) or `input.required<T>()` (mandatory) as **`readonly` class fields**:

  ```typescript
  readonly card = input.required<Card>();
  readonly fontSize = input<'sm' | 'md' | 'lg'>('md');
  readonly loading = input.required<boolean>();
  readonly hint = input<string | null>(null);
  ```

- `input.required()` for inputs the component cannot function without; plain `input()` for optional ones — never pass `undefined` where a default is expected.
- Access values in templates with call syntax: `card()`; derive with `computed()` when transforming.
- Do not use `@Input()` / `@Output()` decorators, `ngOnChanges`, or `SimpleChanges` in new components (signal inputs are the project standard).

## Outputs

- Use `output<T>()` for events:

  ```typescript
  readonly saved = output<Card>();
  readonly deleteRequested = output<void>();
  ```

- Emit with `this.saved.emit(value)`. Do **not** prefix emit names with `on` or `Change` unless a specific alias is required; rely on Angular's `change` naming only through `model()`.

## Two-way binding: `model()`

- Use `model<T>()` when a component participates in two-way binding (`[(value)]`, `[(draft)]`), e.g. draft editors:

  ```typescript
  readonly draft = model<CardDraft>();
  ```

- In templates: `[ngModel]="value()"` + `(ngModelChange)="value.set($event)"` for form fields, or direct `[(value)]` at usage sites.
