# Goal: Keep routing consistent — lazy, guarded, and with proper loading/not-found handling.

## Lazy loading (project pattern)

- All feature pages are lazy-loaded via `loadComponent` in `src/app/app/app.routes.ts` — never `loadChildren`/NgModule lazy loading (see `02.architecture.02.lazy-loading.rule.md`).
- No feature TypeScript module may end up in the initial chunk.
- Nested routes use the same `loadComponent` pattern for child components (tabs, sub-pages).

## Route organization

- Group routes by domain with section comments (`// ── Home ──`, `// ── Card Select ──`, …).
- Use `redirectTo` for aliases and legacy paths (e.g., `tools/card-editor` → `/tools/cards`).
- Every route group with children ends with a wildcard redirect to its default child: `{ path: '**', redirectTo: '<default>', pathMatch: 'full' }`.
- The root shell ends with a global fallback: `{ path: '**', redirectTo: 'home' }` — keep it as the last route.

## Guards

- Use functional guards (`canMatch` / `canActivate`) — no class-based guards.
- Place guard files next to the feature they protect (`*.guard.ts`, see `03.angular.07.naming.rule.md`).
- Prefer `canMatch` over `canActivate` when the guard decides whether a route should be considered at all (e.g., feature availability); use `canActivate` for access control on an already-matched route.
- Feature-scoped providers for guards go in the route's `providers` array (see `02.architecture.03.di-providers.rule.md`).

## Loading & error states

- Lazy-loaded routes should render a loading state while the chunk loads — use `@defer` blocks or a route-level loading component; do not leave a blank screen.
- Data loading states are managed with signals (`loading` / `error` / `data`), see `03.angular.03.reactive.rule.md` and the `async-state` types in `shared/types/`.

## Route metadata

- Set `title` on routes for meaningful document titles (e.g., `title: 'Card Select'`); use `Route.title` or a `TitleStrategy` if a global pattern is needed.
- Keep route paths kebab-case and stable — changing a path requires updating redirects, links, and smoke tests (`*.smoke.spec.ts`).
