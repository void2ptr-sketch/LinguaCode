# Goal: Keep form implementation consistent with the established project pattern.

## Project pattern: template-driven forms (FormsModule)

- The project uses **template-driven forms** with `FormsModule` — `[ngModel]` + explicit `(ngModelChange)` handlers. There is **no `FormBuilder`/`FormGroup`/`FormControl`** in the codebase.
- New form UI (editors, wizards, settings panels) must follow the same pattern unless the task explicitly requires reactive forms.

  ```html
  <mat-form-field appearance="outline">
    <mat-select [ngModel]="draft().source" (ngModelChange)="updateSource($event)">
      @for (language of languages; track language) {
        <mat-option [value]="language">{{ languageLabels[language] }}</mat-option>
      }
    </mat-select>
  </mat-form-field>
  ```

## Draft objects and change handlers

- Mutations are handled by **explicit methods on the component/store that update a signal-based draft** (`draft = signal<Draft>(...)` — see `02.architecture.07.stores.rule.md`). Do not bind `ngModel` two-way directly to immutable store state.
- Use `model()` for reusable field components that participate in two-way binding (see `03.angular.10.signal-inputs.rule.md`).

## Dirty state

- Dirty detection follows `docs/PATTERNS/PATTERN-DIRTY-STATE.md` (signal-based `dirty()` computed from draft vs. initial). The Save button is disabled until `dirty()` (see `course-builder-dialog`, `card-editor-dialog`).
- On discard/cancel with unsaved changes, confirm via a discard dialog (`card-editor-discard-dialog` pattern) — do not silently lose edits.

## Validation

- Simple validation via `computed` signals on the draft, e.g. `languagePairInvalid()` (languages must differ), `title.trim()` checks, required-option counts.
- Show errors inline next to the field; keep error messages user-friendly and in Russian (see `04.design.04.i18n.rule.md`).
