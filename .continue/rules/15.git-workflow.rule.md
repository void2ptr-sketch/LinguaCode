# Goal: Follow the project Git workflow (branch naming, commits, merge).

Full source of truth: `docs/SYSTEM/GIT-RULES.md`. Summary below.

## Branching

- Every task starts from an up-to-date `main`:
  ```bash
  git checkout main && git pull
  git checkout -b NUMBER_description
  ```
- One task = one branch. Never commit directly to `main`. Do not mix unrelated tasks in one branch.
- Branch name format: `NUMBER_description` — task number, `_`, short English slug (lowercase, words joined with `-`).
  - Examples: `1_init-docs`, `2_init-angular`, `3_add-layout`.
- `NUMBER` = max numeric prefix found in existing local/remote branches and `main` commit messages (`[NUMBER_description] …`) + 1; if none found, `NUMBER = 1`.

## Commits

- Format: `[NUMBER_description] краткое описание` — the `[…]` prefix is the **branch name** (identical for all commits in the branch).
- Description after the brackets: what was done, up to ~72 chars, Russian or English, concise. Do not paste the full prompt text.

```bash
git commit -m "[2_init-angular] add header and footer layout"
```

## Push & Merge

- Push the branch **before merge** when work is complete: `git push -u origin NUMBER_description`.
- Push is performed by the **user**, not the AI (unless agreed otherwise).
- Merge method: **merge commit** (`--no-ff`), not squash, not rebase into `main`.
- Merging into `main` is done by the **AI**.
- **Do not delete branches after merge** (neither local nor remote).
- Before merge, verify the build and tests: `ng build` and `npm test`.

```bash
git checkout main && git pull
git merge --no-ff NUMBER_description -m "Merge branch 'NUMBER_description'"
git push origin main
```

## Forbidden

- Force push to `main` (`git push --force`).
- Committing `.env`, keys, passwords, or any secrets.
- Mixing unrelated tasks in one branch.
