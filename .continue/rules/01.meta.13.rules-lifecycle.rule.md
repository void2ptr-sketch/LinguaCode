# Goal: Make `.continue/rules/` self-improving — rules evolve with the system instead of going stale.

## Triggers — events that REQUIRE a rule update

| Event | Required action |
| ----- | --------------- |
| `package.json` / `angular.json` / `tsconfig.json` changed | Update every rule citing those commands/flags/thresholds **in the same change** |
| A rule was violated during review | Analyze: bad wording or wrong fact? Fix the rule, not only the code |
| The assistant asked a clarifying question | The rule is ambiguous → reword it more precisely |
| The same mistake repeated after a rule applied | The rule is ineffective → rewrite or archive it |
| A rule has not been applied for a long time | Check its scope: wrong `globs`? missing `alwaysApply`? |
| Major Angular / TypeScript upgrade | Mass revision of `angular` and `typescript` domain rules |

## Review cycle

- Every rule carries `lastReviewed` + `reviewInterval`; [`scripts/audit-rules.mjs`](../../scripts/audit-rules.mjs) warns when a rule is older than its interval.
- When a rule is outdated: verify its facts against real configs (see `01.meta.09.rules-maintenance.rule.md`), reword if ambiguous, then set `lastReviewed` to today.
- Do not merge while `npm run audit:rules` reports violations — `verify` includes it.

## Adding / archiving rules

- New rule: take the next free NZ in the domain (numbering rules in `01.meta.09.rules-maintenance.rule.md`), then register it in `CONTINUE.md` §8 under the matching domain.
- Archiving: move the content to the "Obsolete rules" section of `CONTINUE.md` with a reference to the replacement — do not silently delete.

## Changelog

- Record every rule add / edit / archive in [`docs/SYSTEM/RULES-CHANGELOG.md`](../../docs/SYSTEM/RULES-CHANGELOG.md) (date, rule, what changed, commit).
