# Goal: Produce consistent, maintainable styles following project conventions.

## Core rules

- **SCSS only** — styles live in component-scoped files: `*.component.scss` next to the component.
- **No inline styles** in templates unless absolutely necessary; prefer component-scoped SCSS.
- **CSS Grid for layout** — prefer `display: grid` with named areas (`grid-template-areas`) over flexbox for page/section layout. This is the established project pattern (see `main-layout`, `main-header`, card components).
- **BEM-like naming** — block `__element` (e.g., `.shell__header`, `.sound-card__stimulus`). Avoid deep nesting; keep selectors flat.
- **Material Design 3 tokens** — use `var(--mat-sys-*)` tokens (e.g., `--mat-sys-outline`, `--mat-sys-primary`) instead of hard-coded colors. Use `color-mix(in srgb, var(--mat-sys-outline) 30%, transparent)` for translucent variants.
- **Spacing** — use `gap` on grid/flex containers; prefer `rem` units for spacing and sizing.
- **Responsive** — use `@media (max-width: …)` / `(min-width: …)` breakpoints; collapse grid areas to a single column on narrow screens.

## Shared SCSS

- Reuse shared partials with `@use` (e.g., card components: `@use '../quiz-card';`). Never use `@import` (deprecated).
- Global theme setup lives in `src/styles.scss` (`@use 'theme/app-color-schemes';`, `@use 'theme/code-highlight-theme';`).
- Do not duplicate shared styles across components — extract to a partial and `@use` it.

## Grid layout example (project pattern)

```scss
.shell {
  display: grid;
  grid-template-areas:
    'header header'
    'nav    main'
    'footer footer';
  grid-template-columns: 14rem 1fr;
  grid-template-rows: auto 1fr auto;
  min-height: 100vh;
}

.shell__header { grid-area: header; }
.shell__nav    { grid-area: nav; }
.shell__main   { grid-area: main; }
.shell__footer { grid-area: footer; }

@media (max-width: 768px) {
  .shell {
    grid-template-areas:
      'header'
      'nav'
      'main'
      'footer';
    grid-template-columns: 1fr;
  }
}
```

## Angular Material

- Use Angular Material components for UI (theme: `azure-blue`).
- Do not fight Material internals with `::ng-deep` unless there is a documented need; prefer Material theming tokens and component APIs.
- Avoid `ViewEncapsulation.None` unless documented (see `03.angular.02.build.rule.md`).

## Formatting

- Run `npm run format` / `npm run format:fix` (Prettier) before finishing — SCSS is included in the format globs.
