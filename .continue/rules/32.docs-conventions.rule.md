# Goal: Keep the `docs/` tree structured, discoverable, and in sync with code.

## Structure & naming

- Categories and file-name prefixes (existing convention):
  - `docs/ARCHITECTURE/*.md` — per-slice architecture notes (`ARCHITECTURE.<slice>.md`).
  - `docs/CARDS/*.md` — card type specs (`card-<type>.md`).
  - `docs/COMMON/*.md` — cross-cutting domain docs (`DOMAIN.md`, `CARD-CATALOG.md`, `CARD-FIELD-GUIDE.md`).
  - `docs/CONTENT/*.md` — language content (`CJK-CONTENT.md`, `PHONETIC-CONTENT.md`).
  - `docs/FEATURES/*.md` — feature specs (`COURSE-BUNDLE.md`, `EDITOR-UX.md`, `LANGUAGE-PAIR.md`, `SCENARIO-BUILDER.md`).
  - `docs/PATTERNS/*.md` — reusable UI/state patterns (`MODAL-DIALOG.md`, `PATTERN-DIRTY-STATE.md`).
  - `docs/SYSTEM/*.md` — process/system docs (`GIT-RULES.md`, `MOCK-DATA.md`, `barrel-exports-audit.md`).
- Top-level docs: `README.md`, `TASKS.md`, `docs/INDEX.md`, `docs/ARCHITECTURE.md`, `docs/BUSINESS.md`, `docs/API-CONTRACT.md`.
- New docs go into the matching category; uppercase snake-case file names, category prefix first.

## When to update

- **Anything that touches public API, behavior, or architecture** → update the relevant doc in the same task:
  - API endpoints → `docs/API-CONTRACT.md` (see `24.env-api-contract.rule.md`).
  - Domain/card models → `docs/COMMON/DOMAIN.md`, `docs/COMMON/CARD-CATALOG.md`.
  - Content/phonetics → `docs/CONTENT/*`.
  - Architecture decisions → `docs/ARCHITECTURE.md` / `docs/ARCHITECTURE/*`.
- Every doc change must keep `docs/INDEX.md` (table of contents) in sync.
- Status markers (e.g. `> **Статус:** готово (G11)`) reference `TASKS.md` task IDs — update when the corresponding task state changes.

## Doc formatting

- Each doc starts with linked related documents (`Связанные документы`: `INDEX.md`, domain docs, `TASKS.md`).
- Keep markdown clean and consistent with the repo's Prettier config (`npm run format` covers `docs/**/*.md`).
- Do not duplicate large blocks between docs — link instead (`.continue/rules/` is the place for developer rules, not architecture prose).
