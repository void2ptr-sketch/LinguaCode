# Goal: Keep the app fast — bundle sizes, rendering, and asset loading.

## Build & bundle

- Respect `angular.json` **budgets**; never silently exceed them. If a budget is genuinely too tight, adjust it deliberately and note the reason in the commit.
- Route-level lazy loading with `loadComponent` is mandatory (see `02.architecture.02.lazy-loading.rule.md`); no feature code may end up in the initial chunk.
- For bundle analysis use `source-map-explorer` (devDependency) after `npm run build`.

## Rendering

- `ChangeDetectionStrategy.OnPush` everywhere (see `02.architecture.06.component-patterns.rule.md`).
- `@for` loops must have a stable `track` key to minimize DOM churn (see `03.angular.09.control-flow.rule.md`).
- Prefer `computed` signals over template method calls and `async` pipe where signals suffice (see `03.angular.03.reactive.rule.md`).

## Deferred loading

- Use `@defer (on viewport | on idle | on interaction)` for heavy or below-the-fold UI — the established pattern for `pinyin-keyboard` and `draw-canvas`.
- Always supply `@placeholder`/`@loading` with minimal stable size to avoid layout shift (CLS).

## Assets

- Use `NgOptimizedImage` (`ngSrc`) for images with `width`/`height` or `fill`, provide `priority` for LCP images.
- Hanzi stroke data is large — keep the `hanzi-stroke-data` asset group lazy in `ngsw-config.json` (see `05.business.04.pwa.rule.md`).
- Do not load large data files eagerly; rely on `ContentSeedRepository` caching (IndexedDB).

## Profiling

- When investigating slowness, profile with Angular DevTools (change detection) and the browser performance panel; fix root causes, not symptoms (see `CONTINUE.md` §7).
