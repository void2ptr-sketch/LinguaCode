# Goal: Prevent common security pitfalls.

# Security rules:

## Input & rendering
- Sanitize user input when rendering HTML; never bind directly to `[innerHTML]` without sanitization.
- Use the project's sanitization utilities in `src/app/shared/security/` — do not invent custom sanitizers.
- Validate and sanitize URLs before using them in redirects or dynamic imports.
- Use Angular's built-in security mechanisms (DOM sanitization, XSS protection) instead of custom solutions.

## Storage & secrets
- Avoid storing sensitive data in localStorage unless encrypted and justified.
- **Never commit secrets, tokens, keys, or passwords** — `.env` is gitignored; use `.env.example` as a template with placeholders only.
- Do not hard-code API keys or tokens in source code or `src/environments/`.

## Dependencies
- Run `npm run audit` (`npm audit --audit-level=high`) after dependency changes; fix or justify high/critical vulnerabilities.
- Do not add new dependencies without checking their maintenance status and security history.

## PWA / service worker
- Do not cache sensitive user data in the service worker (see `05.business.04.pwa.rule.md`).
- Keep `ngsw-config.json` data groups scoped to `/api/**` with freshness strategy; do not broaden caching to sensitive endpoints.

## General
- Follow the principle of least privilege for providers and guards (see `02.architecture.03.di-providers.rule.md`).
- When generating code, watch for security holes the AI may introduce (unsafe `innerHTML`, missing validation, exposed secrets) — review before committing.
