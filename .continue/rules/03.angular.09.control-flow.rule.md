# Goal: Enforce the built-in control flow syntax (Angular 17+) in all templates.

The codebase uses the new control flow **exclusively** — `*ngIf`/`*ngFor`/`*ngSwitch` are legacy and must not appear in new code.

## Rules

- **`@if` / `@else if` / `@else`** instead of `*ngIf`. Use the `as` alias for nullable values (project pattern):

  ```html
  @if (card(); as card) {
    <app-card-host [card]="card" />
  } @else {
    <div class="empty">Нет карточки</div>
  }
  ```

- **`@for` with a mandatory `track`** instead of `*ngFor`:
  - Use a stable unique key (`track item.id`, `track item.path`). Use `track $index` only when no stable key exists (short static lists).
  - Use the block variables: `let index = $index`, `let last = $last`, `let first = $first`, `let count = $count`.
  - Do **not** use `*ngFor`'s `trackBy` — `track` is the built-in equivalent.

- **`@switch` / `@case` / `@default`** instead of `*ngSwitch` / `*ngSwitchCase` (see `card-host.component.html`, `card-form.component.html`).

- **`@defer (on viewport | on idle | on interaction | when …)`** for heavy or non-critical UI — deferred components must not block the initial render:
  - Already used: `pinyin-keyboard` and `draw-canvas` (`@defer (on viewport)`).
  - Always provide `@placeholder` / `@loading` blocks with a minimal size to avoid layout shift.

- **`@let`** (Angular 18+) allowed for computed expressions reused multiple times in one template; do not overuse it for trivial one-off expressions.

- Empty blocks: `<div class="x" />` self-closing style is fine; keep consistent with surrounding code.
