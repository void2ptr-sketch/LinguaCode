# Project Architecture

This is an Angular application (Angular 22, TypeScript 6, standalone components, Signals). Adhere strictly to the defined structure.

## FSD Layers (Feature-Sliced Design, 6 layers)

Imports are strictly downward. Verification: `npm run audit:fsd` (`node scripts/audit-fsd.mjs`).

```
src/app/
├── app/        # composition: app.config, app.routes, provide-api, interceptors, theme, errors
├── pages/      # route pages (*-page components), lazy-loaded via loadComponent
├── widgets/    # reusable UI: main-layout, header, footer, sidebar-navigation, menus
├── features/   # isolated features (card-select, card-editor, course-builder, …)
├── entities/   # domain slices: card, course, lesson, scenario, user, learning,
│               #   language-pair, phonetic, chinese, content-seed, journey, auth
└── shared/     # domain-agnostic code: utils, security, api, storage, sync, theme, types, ui, logger
```

### Import direction rules

| Layer      | May import                                                        |
| ---------- | ----------------------------------------------------------------- |
| `app`      | everything below                                                   |
| `pages`    | widgets, features, entities, shared                                |
| `widgets`  | features, entities, shared                                         |
| `features` | entities, shared                                                   |
| `entities` | shared                                                             |
| `shared`   | nothing from `src/app` (external packages only)                    |

- **Features must not import each other** (cross-slice imports are forbidden).
- The public API of a feature/slice is exposed through its `index.ts` barrel (see `03.angular.07.naming.rule.md` and `CONTINUE.md` §9 for export order).
- There is **no `src/app/core/`** — it was removed during the FSD migration. Infrastructure lives in `app/`, `shared/`, `entities/`, or `widgets/` depending on its layer.
- When moving files, update relative imports (the `../` depth depends on the new location) and run `npm run check:imports` + `npm run audit:fsd` + `npm run audit:barrels`.

### Key Configuration Files
*   **`src/app/app.config.ts`** — Application configuration (providers, initializers, content seed preloading, auth session restore).
*   **`src/app/app.routes.ts`** — Routing configuration (lazy `loadComponent` only).
*   **`src/environments/environment.ts`** — Environment configuration.
*   **`angular.json`** — Build/test targets (`@angular/build:unit-test`, Vitest runner).

# Coding Standards

### 1. Core Architecture
*   **Standalone Only:** Use standalone components exclusively. Never use `NgModule`.
*   **TypeScript:** Write all new files strictly in TypeScript (strict mode).
*   **Naming Conventions:** Follow `03.angular.07.naming.rule.md` without exceptions.
*   **Components Suffix:** Use the `.component.ts` suffix for all component files.

### 2. State & Data Types
*   **State Management:** Prioritize **Angular Signals** for state management. Minimize RxJS usage (see `03.angular.03.reactive.rule.md`).
*   **Type Definitions:** Prefer `type` over `interface` for all data structures and models.

### 3. Testing & Quality Guardrails
*   **Test Coverage:** Write comprehensive tests for all new features.
*   **Testing Framework:** Use **Vitest** (`*.spec.ts`, `types: ["vitest/globals"]`, runner `vitest` in `angular.json`).
*   **Code Formatting:** Follow Prettier standards: single quotes, trailing commas, semicolons (see `.prettierrc`).

### 4. Language Requirements
*   **Code Identifiers:** Write all variables, functions, and classes strictly in English.
*   **Documentation:** Write comments, docstrings, and commit messages in either Russian or English.
