# Goal: Keep the frontend (Angular) and backend (java) contracts in sync.

## Repositories

- **Frontend:** `/home/alex/workspace/Angular.LinguaCode` (this repo).
- **Backend:** `/home/alex/workspace/java.LinguaCode` — access only within the scope stated in `01.meta.01.agent-behavior.rule.md` and only when the user explicitly asks for backend work.

## API contract workflow

- `docs/API-CONTRACT.md` is the **single source of truth** for the HTTP contract (see `05.business.05.env-api-contract.rule.md`).
- Any endpoint change must update, in the same task:
  1. `docs/API-CONTRACT.md`;
  2. the API service (`entities/<slice>/api/*.service.ts`);
  3. the port (`entities/<slice>/repository/*.port.ts`);
  4. the mock interceptor (`entities/<slice>/api/mock/*.mock.interceptor.ts`);
  5. conformance tests (`*.conformance.spec.ts`, see `03.angular.12.smoke-conformance.rule.md`).
- Mocks are enabled by environment flags (`useCardsApiMock`, `useScenariosApiMock`, `useCoursesApiMock`) — the frontend can be developed against mocks before the backend endpoint exists (see `docs/SYSTEM/MOCK-DATA.md`).

## Versioning & breaking changes

- `apiVersion` comes from `environment.apiVersion`; **do not change it without a migration plan** for existing endpoints (see `05.business.05.env-api-contract.rule.md`).
- Flag breaking changes explicitly in `docs/API-CONTRACT.md` (e.g. a `## Breaking changes` note or version table) so frontend and backend teams migrate together.
- If the backend contract is unknown/not implemented, state that clearly instead of inventing endpoint shapes.
