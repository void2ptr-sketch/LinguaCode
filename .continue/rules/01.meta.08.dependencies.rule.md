# Goal: Keep the dependency set minimal, secure, and locked.

## Rules

- **Check `package.json` before assuming a library exists** (see `01.meta.04.tasks-workflow.rule.md`) — do not propose a new dependency when the built-in API, Angular Material, or an existing package suffices.
- **New dependencies require justification** — add only after checking:
  - maintenance status and release history (deprecated/unmaintained → reject);
  - security history (known CVEs);
  - bundle size impact (see `03.angular.13.performance.rule.md`);
  - license compatibility when relevant.
- Use `npm install <pkg>` (updates `package.json` + `package-lock.json`) and **commit the lockfile** — CI uses `npm ci`.
- Keep versions aligned with the existing range style (`^` / `~` as in `package.json`); do not mix registries or pin exact floating versions without reason.
- Prefer **Angular Material / CDK** for UI and **built-in Angular APIs** (signals, `http`, router) over external utilities.
- After dependency changes run:
  ```bash
  npm run audit        # npm audit --audit-level=high
  npm run verify       # full pipeline
  ```
- Do not remove a dependency that is still referenced; check imports first (see `02.architecture.04.fsd-imports.rule.md`).
