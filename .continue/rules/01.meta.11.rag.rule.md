# Goal: Get reliable answers in complex or unclear cases by searching the internet instead of guessing or hallucinating.

## Source priority

Use knowledge sources in this order — only move to the next level when the answer is still unclear:

1. **Local context** — project files, `.continue/rules/`, `docs/`, the current conversation/RAG context.
2. **Codebase search** — `search_files`, reading the actual source (docs may lag behind the code).
3. **Internet search** — official docs, framework release notes, Stack Overflow, GitHub issues/PRs.

## When to search the internet

Search (via `web_fetch`, browser, or search tool) when the case is complex or unclear:

- Unfamiliar API, deprecation notice, or a framework feature not present in the local context.
- An error message that the codebase/docs do not explain.
- Choosing between several possible approaches where trade-offs are not documented locally.
- A version-specific question: the project uses **Angular 22+ / TypeScript 6+** — behavior may differ from older versions.
- New or changed APIs after the local docs were written (docs drift — see `01.meta.06.docs-conventions.rule.md`).

## How to use internet sources

- **Cite the source** in the answer (URL / doc title), e.g. "As per Angular docs: …".
- **Do not copy code blindly** — adapt external examples to project conventions (standalone components, signals, FSD imports, strict TS).
- **Prefer official sources** (angular.dev, nodejs.org, typescriptlang.org, npm package READMEs) over random blogs.
- **Check the version** the source describes against the project versions (`package.json`, `.nvmrc`) before relying on it.
- **Mark uncertainty**: if the external info contradicts local context, state the conflict and verify before applying.

## What NOT to do

- Do not search for facts already present in the local context/RAG data — synthesize from context first.
- Do not search when the user expects a local answer (project structure, existing code).
- Do not guess or invent when a search is possible; do not hallucinate when it is not — say "not found/insufficient information" instead (see `01.meta.01.agent-behavior.rule.md`).
- Do not loop on failed searches — change the query/approach (see `01.meta.10.anti-looping.rule.md`).
