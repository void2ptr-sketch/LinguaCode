# Angular Naming Conventions

## Purpose
Enforce consistent, readable, and maintainable naming across the Angular project. These rules apply to all newly generated and refactored code.

## Files
- File names use kebab-case.
- Each file name ends with a suffix that indicates its type.
  - Components: `my-feature.component.ts`
  - Services: `user.service.ts`
  - Guards: `auth.guard.ts`
  - Resolvers: `user-details.resolver.ts`
  - Pipes: `currency.pipe.ts`
  - Directives: `highlight.directive.ts`
- Folders use kebab-case and reflect the feature or domain.
  - Example: `src/app/user-profile`, `src/app/shopping-cart`.

## Components
- Component class names use UpperCamelCase with a descriptive prefix and end with `Component`.
  - Examples: `UserProfileComponent`, `ShoppingCartSummaryComponent`.
- Template and style files share the same base name as the component class, in kebab-case with the appropriate suffix.
  - `user-profile.component.html`
  - `user-profile.component.scss`
- Component selectors use kebab-case prefixed with a consistent scope prefix (e.g., `app-` or project-specific prefix).
  - Examples: `app-user-profile`, `prj-shopping-cart-summary`.

## Services, Guards, Resolvers, Pipes, Directives
- Class names use UpperCamelCase and end with the corresponding suffix: `Service`, `Guard`, `Resolver`, `Pipe`, `Directive`.
  - Examples: `UserService`, `AuthGuard`, `OrderDetailsResolver`, `CurrencyPipe`, `HighlightDirective`.

## Interfaces and Types
- Use UpperCamelCase.
- Avoid unnecessary prefixes like `I` or `T`.
  - Good: `User`, `OrderDetails`, `ApiResponse`.
  - Bad: `IUser`, `TOrder`.
- Project convention: prefer `type` aliases for data structures and models (see `06.angular.TypeScript.rule.md`); use `interface` mainly for class contracts when required.

## Enums
- Use UpperCamelCase for enum names.
- Enum members use UPPER_CASE.
  - ```ts
    export enum OrderStatus {
      Pending = 'PENDING',
      Processing = 'PROCESSING',
      Shipped = 'SHIPPED'
    }
    ```

## Variables, Properties, and Methods
- Use camelCase for variables, properties, and methods.
  - Examples: `userId`, `cartItems`, `calculateTotal()`, `loadUserDetails()`.

## Constants
- Use UPPER_CASE with underscores.
  - Examples: `MAX_RETRY_COUNT`, `DEFAULT_TIMEOUT_MS`.

## Template Variables and Event Bindings
- Use kebab-case for template reference variables and event names in HTML.
  - `<input #searchInput ...>`
  - `(click)="onSearch()"`

## Prefixes and Scope
- Do not use generic prefixes like `My`, `Custom`, or `New` unless they are part of the domain language.
- Use domain-specific terms for clarity: `User`, `Order`, `Payment`, `Notification`.
- For scoped components/features, rely on folder structure and selector prefix instead of prefixing class names.

## Standalone Components and Lazy Modules
- Standalone components still follow the same naming rules; their “standalone” nature is expressed via `standalone: true` in the decorator, not in the name.
- Lazy-loaded feature modules (if used) should have names that reflect the feature domain, e.g., `UserProfileModule`, `ShoppingCartModule`.

## Module Names (if applicable)
- Use UpperCamelCase ending with `Module`.
  - Examples: `CoreModule`, `SharedModule`, `UserProfileModule`.

## Validation Rules for Code Generation
When generating or refactoring code:
- If any name violates these conventions, fix it before committing changes.
- If a legacy name conflicts with these conventions, add a brief comment explaining the exception only if the name cannot be changed immediately; prioritize renaming in a dedicated refactor task.
- Do not introduce new naming styles inconsistent with this rule.

## Examples of Correct vs. Incorrect

| Item | Incorrect | Correct |
|------|-----------|---------|
| Component file | `MyUser.ts` | `user-profile.component.ts` |
| Component class | `MyUserComponent` | `UserProfileComponent` |
| Service class | `userService.ts` / `userService` | `user.service.ts` / `UserService` |
| Interface | `IOrder` | `Order` |
| Constant | `maxRetry` | `MAX_RETRY_COUNT` |

## Exceptions
- Third‑party libraries and external APIs retain their original naming.
- Generated code from external tools (e.g., CLI scaffolding, build outputs) is exempt, but hand‑written code must follow these rules.
