# Goal: Enforce Feature-Sliced Design (FSD) layer boundaries and import direction.

The project uses FSD with 6 layers. Imports are strictly **downward** — a module may import from its own layer or any layer below it, never from a layer above.

## Layer order (bottom → top)

```
shared (bottom) → entities → features → widgets → pages → app (top)
```

| Layer      | May import                                                        | Must NOT import |
| ---------- | ----------------------------------------------------------------- | --------------- |
| `app`      | pages, widgets, features, entities, shared                        | —               |
| `pages`    | widgets, features, entities, shared                               | `app`           |
| `widgets`  | features, entities, shared                                        | `pages`, `app`  |
| `features` | entities, shared                                                  | `widgets`, `pages`, `app` |
| `entities` | shared                                                            | `features`, `widgets`, `pages`, `app` |
| `shared`   | nothing from `src/app` (external packages only)                   | any `src/app` layer |

## Hard rules

1. **No upward imports.** A file in `features/` must never import from `widgets/`, `pages/`, or `app/`. A file in `entities/` must never import from `features/` or above.
2. **No cross-slice imports between features.** Features are isolated: `features/card-editor/` must not import from `features/card-select/` (or any other feature slice). Shared logic between features must be extracted to `entities/` or `shared/`.
3. **`shared/` is domain-agnostic.** It must not import anything from `src/app` — only external packages (Angular, RxJS, etc.).
4. **Public API via `index.ts`.** Each feature/slice exposes its public API through a barrel `index.ts`. Consumers import from the slice root (`features/card-select`), not from deep internal paths. Layer root barrels (e.g. `features/index.ts`) are the layer's public API and are exempt from the cross-slice check.
5. **No `src/app/core/`.** The `core/` layer was removed during the FSD migration. Infrastructure belongs in `app/`, `shared/`, `entities/`, or `widgets/` depending on its layer.

## When moving or creating files

- Place new code in the correct layer: pages → `pages/`, reusable UI → `widgets/`, isolated feature logic → `features/<name>/`, domain models/repositories → `entities/<name>/`, generic utilities → `shared/`.
- After moving a file, **update all relative imports** — the `../` depth depends on the new location.
- Keep cohesive modules together (see `03.angular.07.naming.rule.md` — folders that must not be split).

## Verification (run before completing a task)

```bash
npm run audit:fsd       # layer direction + cross-slice check (node scripts/audit-fsd.mjs)
npm run check:imports   # every relative import resolves to an existing file
npm run audit:barrels   # barrel export consistency (index.ts)
```

- `audit:fsd` checks: (1) layer direction — a module may only import from its own layer or layers below; (2) cross-slice imports between features (layer root barrels like `features/index.ts` are excluded).
- `check:imports` verifies each relative import resolves to a real file (exact, `+ .ts`, or directory with `index.ts`).
- Exit code 0 = clean, 1 = violations. Fix all violations before finishing the task.
